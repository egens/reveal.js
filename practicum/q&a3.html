Хранение чисел

32 bit Integer
65 = 2^6 + 2^0
32 bit Float (IEEE 754)
10.75 = 1010.11 = 1.01011 * 2³
Давайте разберем, как компьютеры хранят числа – это фундамент, на котором строятся все вычисления в Java.
Кто знает разницу между битом и байтом?
А кто готов объяснить, что такое мантисса?


Отлично! Напомню: Бит – это минимальная ячейка (0 или 1)
Байт = 8 бит – как раз размер символа ASCII
Мантисса – ключевая часть чисел с плавающей точкой, о ней через минуту


В основе компьютерной архитектуры лежат нули и единицы — двоичная система счисления. Когда мы пишем программу, мы оперируем машинными числами. Примитивные типы, ссылки на объекты, даже строки — все можно представить в виде набора битов. Строковые символы связаны со своими кодами через таблицы кодировок, с которыми многие уже успели познакомиться.

На примере напомню про хранения целых чисел и чисел с плавающей точкой.
Целое число 65 раскладывается на степени двойки: 65 = 2⁶ + 2⁰ (64 + 1) и хранится как 0100 0001
Фишка Java: Все типы вроде byte, int, long используют этот принцип

Дробное число 10.75 переводится в двоичный вид 1010.11
Дальше выполняется нормализация: 1.01011 × 2³ (сдвигаем точку на 3 позиции)
Из этого представления можно составить двоичное представление, оно состоит из трех частей:
Знак (1 бит): + или -, Экспонента (8 бит): степень (здесь 3), Мантисса (23 бита): дробная часть (здесь .01011)

Давайте ответим на вопрос — сколько всего разных чисел можно представить в Float? 2^32 это примерно 4 миллиарда. Обратите внимание, что максимальное значение для float 10^38 степени. Это 38 нулей. То есть максимальное значение гораздо больше количества чисел в диапазоне. Это говорит о том, что даже если взять только целые числа из диапазона, мы сможем без потери точности представить только малую часть из них. На самом деле, если взять все числа, которые можно записать в float и разместить их на числовой оси — получится картина внизу. Вокруг нуля плотность будет очень высокой, а для больших значений наоборот очень низкой.

ФП3 Конструктор обеда

  • Main — меню
  • DinnerConstructor — логика
  • Ключ — тип блюда, значение — список названий блюд
Поставьте + кто решил и - кто не решил. В этом спринте мы пишем небольшое консольное приложение конструктор обедов.

Вам нужно последовательно наполнить несколько классов кодом. В ТЗ есть подсказки, попробуйте без них. Алгоритмы работы приложения нужно будет написать самому.

На экране будет код решения. Вы можете подглядывать в него при выполнении ДЗ, но очевидно, что самостоятельная работа гораздо эффективнее для вашего обучения. 


			public class DinnerConstructor {

				HashMap> dinnersByType = new HashMap<>();
				Random random = new Random();

				public void addNewDish(String dishType, String dishName) {
					ArrayList dishesForType;
					if (dinnersByType.containsKey(dishType)) {
						dishesForType = dinnersByType.get(dishType);
					} else {
						dishesForType = new ArrayList<>();
						dinnersByType.put(dishType, dishesForType);
					}

					dishesForType.add(dishName);
				}

				public ArrayList> generateCombos(int comboNumber, ArrayList dishTypes) {
					ArrayList> combos = new ArrayList<>();
					for (int i = 1; i <= comboNumber; i++) {
						ArrayList combo = generateCombo(dishTypes);
						combos.add(combo);
					}
					return combos;
				}

				private ArrayList generateCombo(ArrayList dishTypes) {
					ArrayList selectedDishes = new ArrayList<>();
					for (String dishType: dishTypes) {
						ArrayList availableDishes = dinnersByType.get(dishType);
						int numberOfDishesForType = availableDishes.size();
						int dishIndex = random.nextInt(numberOfDishesForType);
						String selectedDish = availableDishes.get(dishIndex);
						selectedDishes.add(selectedDish);
					}
					return selectedDishes;
				}

				public boolean checkType(String type) {
					return dinnersByType.containsKey(type);
				}
			}
