Вас познакомили с оставшимися двумя принципами ООП.

Абстракция — связана с инкапсуляцией. Заключается в создании абстрактных моделей или интерфейсов, чтобы скрыть детали их внутренней реализации и предоставить только необходимый интерфейс для взаимодействия с объектами. Позволяет разработчику сфокусироваться на том что делает класс, а не как он это делает.

Полиморфизм — способность программы одинаково работать с объектами, если они имеют один интерфейс Виды полиморфизма? Классический полиморфизм; — разные классы имплементируют один интерфейс Ad-hoc полиморфизм, который делится на два подвида: Динамический, — переопределение методов при наследовании Статический; — перегрузка методов Параметрический полиморфизм. — дженерики Дженерики, довольно сложная концепция создания типов с параметрами. Не пугайтесь, если с ходу не поняли, осознание придет с опытом.

До дженериков часто использовали преобразование типов (39-44 строки), что приводило к ошибкам в время исполнения.

Абстракция в Java

  • Суть: Сокрытие сложности через ключевые свойства
  • Инструменты: abstract class и interface
  • Абстрактные классы: нельзя создать, могут быть методы с/без реализации
  • Интерфейсы:Контракт (до Java 8), теперь с default/static/private
  • Цель: Гибкость, расширяемость, разделение "что" и "как"
1. Суть абстракции Абстракция позволяет работать с объектами, выделяя только их ключевые свойства и скрывая детали реализации. Например, когда вы используете коллекции в Java, вам не нужно знать, как именно устроен ArrayList внутри — важно лишь то, что он реализует поведение List.

2. Инструменты В Java абстракция достигается через: Абстрактные классы — могут содержать как абстрактные методы (без реализации), так и обычные. Интерфейсы — изначально были чистыми контрактами, но теперь поддерживают default, static и даже private методы.

3. Абстрактные классы Нельзя создать их экземпляр напрямую (new AbstractClass() вызовет ошибку). Полезны, когда у классов-наследников есть общая логика, но часть поведения должна быть переопределена.

4. Интерфейсы До Java 8 — только абстрактные методы. После Java 8 — появились default-методы (чтобы не ломать старый код) и static-методы (удобные утилиты). С Java 9 — можно использовать private-методы для разбивки сложной логики внутри default-методов.

5. Зачем это нужно? Гибкость — код легче расширять и модифицировать. Упрощение — программист работает с интерфейсом, а не с внутренней реализацией. Разделение ответственности — интерфейс определяет что должно делать, а классы решают как.

Важный нюанс: Абстракция ≠ инкапсуляция. Абстракция — это про упрощение модели, а инкапсуляция — про защиту данных и сокрытие состояния объекта.

Вопрос для обсуждения: Когда лучше использовать интерфейс, а когда — абстрактный класс? (Подсказка: интерфейсы — для слабой связи и множественного наследования, абстрактные классы — если есть общая логика для наследников.)

Полиморфизм в Java

  • Суть: Один интерфейс — множество реализаций
  • Виды:
    • Ad-hoc (перегрузка методов)
    • Параметрический (дженерики)
    • Подтипов (наследование)
  • Механизмы:
    • Переопределение методов (@Override)
    • Ссылки суперкласса на подклассы
  • Польза: Гибкость кода + единая точка расширения
1. Суть полиморфизма Позволяет использовать один и тот же интерфейс для работы с разными типами данных. Например, метод draw() будет по-разному работать для классов Circle и Square, но вызываться одинаково.

2. Основные виды Ad-hoc (перегрузка): Разные методы с одним именем, но разными параметрами (sum(int a, int b) и sum(double a, double b)). Параметрический (дженерики): Один метод/класс работает с разными типами (List(String) и List(Integer)). Подтипов (наследование): Возможность подставлять объекты подклассов вместо родительских классов.

3. Ключевые механизмы Переопределение методов: Аннотация @Override гарантирует, что подкласс меняет поведение метода родителя. Полиморфные ссылки: Возможность хранить в переменной суперкласса объект подкласса (Animal a = new Cat()).

4. Практическая польза Единая точка входа для разных реализаций Упрощение добавления новых типов Поддержка принципа открытости/закрытости Важный нюанс: Полиморфизм подтипов работает только с переопределением методов (не полей!).

Вопрос для обсуждения: Чем отличается перегрузка от переопределения методов? (Подсказка: перегрузка — разные сигнатуры в одном классе, переопределение — та же сигнатура в подклассе)

Разработка на интерфейсах
Давайте поговорим про интерфейсы. Кто может рассказать для чего они нужны? Лучшей практикой в Java является использование интерфейсов вместо имплементаций в типах переменных и параметров.

Но зачем так делать? Простой ответ — нужно применять принцип абстракции, не нужно накладывать на метод дополнительные ограничения. Сложный ответ — это очень важно при разработке центральных компонентов сложной системы.

Не нужно ограничивать метод имплементацией, если она для контракта не важна и достаточно конкретного ее интерфейса. То есть не то как объект устроен внутри, а как с ним можно взаимодействовать снаружи. Потому что внутреннее устройство может измениться.

В итоге чем полезны интерфейсы. Уменьшают связанность кода, если применяются там, где не важна имплементация. Это особенно важно при проектировании ключевых элементов программной архитектуры. Ведут к DRY (dont repeat yourself) — когда можно обойтись одним методом для разных аргументов. Без них невозможно множественное наследование.

Обратите внимание на пример — в 12 и 15 строчках используется интерфейсный тип List. Гораздо важнее использование List в сигнатуре метода filterByGenre, чтобы не привязывать его к конкретной имплементации списка. Использование конкретных типов, то есть ArrayList при создании переменных может считаться плохой практикой — в некоторых командах за этим следят. А теперь про практику — вряд-ли на вашей первой работе разработчиком вы будете писать сложный проект с нуля для core какого-нибудь банка. На реальном проекте лучше будет посмотреть на существующую кодовую базу, обсудить со старшими товарищами и тогда принимать решение.

Выбор методов при перегрузке

  • process(…) — int, double, Integer, Number, Object
  • Для примитивов
    Same type > Auto Widening > Boxing > Upcasting(Parent Class) > Super Class
  • Для ссылочных типов
    Same type > Upcasting(Parent Class) > Super Class > Unboxing
Перегрузка методов — напомню, наличие двух методов с одинаковым названием, но разными типами параметров.

В Java есть определенные правила, которые расписаны на слайде. Этому посвящена отдельная глава спецификации JLS. Они вкратце приведены на слайде и отличаются для ссылочных и примитивных типов.

Когда параметров становится больше одного, выбор метода может стать очень запутанным.

Поэтому, если при написании своего кода вы делаете большое количество перегрузок одного метода, задумайтесь о разделении их на разные методы по именам.

Не пишите код как головоломку!

Вычисление по короткой схеме

Short circuit evaluation
Для строгих вычислений — &, |
В большинстве ЯП есть эта неочевидная концепция. Основная идея заключается в том, что если результат выражения может быть определен на основе значения левой части выражения, то правая часть выражения не вычисляется вообще. Если через && — то до первого false Если через || — то до первого true Часто используется для проверки на существование перед вызовом метода. Также, если проверки затратные по времени, сначало в выражении нужно выполнять менее затратные.
