Функциональный стиль
Опишу ФП немного с другой стороны, чем в лекциях.

ФП — парадигма, при которой процесс вычисления трактуется как вычисление значений функций в их математическом понимании.

ФП основано на математической теории лямбда исчисления. Чистые ФП языки реализуют лямбда исчисление.

Но важно понимать, что ФП это не только про функции. ФП — декларативный стиль, то есть программа описывает что надо получить в результате вычисления.

Процедурное и ООП — императивный подход, то есть по шагам описывается как получать результат.

Java больше предназначен для ООП, потому что изначально развивался как ООП.

Зачем вам ФП — с помощью ФП можно проще решить некоторые задачи, как показано в теории. Лямбды постоянно используются в коде.

Хвостовая рекурсия — в Java ее нет.

Анонимные классы — синтаксический сахар, нужны чтобы не создавать маленькие классы, которые нужно использовать только один раз.

Лямбды — называются из-за лямбда исчисления, дальнейшее упрощение анонимных классов. Это анонимные функции.

Когда анонимный класс можно заменить на лямбду? Если они содержат ровно один метод. Если в них нет полей.

Также вам рассказали про замыкания. Замыкание в общем случае это техника привязки окружающих переменных к функции при ее создании. Иногда такую функцию и называют замыканием. В Java нет чистых замыканий — к переменным есть требование final or effectively final. Для чистых замыканий нужна полная переработка языка, которая может нарушить обратную совместимость. https://stackoverflow.com/a/17204638

Ссылка на метод вместо лямбды — IDEA сама подскажет, если можно заменить.

Optional нужно использовать там, где вы не контролируете переменную. Не нужно им обмазывать все подряд.

Другие классы внутри класса
Хочу рассказать вам про другие варианты объявления классов внутри класса.

Это также синтаксический сахар, который позволяет сгруппировать объекты, улучшить инкапсуляцию, сделать код более читаемым и поддерживаемым.

Локальный класс — внутри метода. Анонимный класс создает один экземпляр, локальный — если нужно создавать больше. Внутренний Nested статический на уровне метода. Как локальный + нужно использовать этот класс в разных методах внешнего.

Вложенный Inner не статический. Как Nested + в этом классе нужен доступ к приватным полям/методам внешнего класса.

Примеры использования есть в стандартной библиотеке — например класс Node в списке, который мы изучали на прошлом вебинаре.

Это постоянно используется при разработке АПИ.

Сколько раз будет выведено PROCESSED? Ответ — ноль, потому что нет терминальной операции.

Intermediate operations are lazy. This means that they will be invoked only if it is necessary for the terminal operation execution.

Время и дата

Как и кодировки — боль разработчиков.

Информацию о текущем времени программа берёт из устройства, на котором она запущена.

На серверах обычно следят за тем, чтобы время было синхронизированным, но может быть небольшой разбег.

Начинает вмешиваться теория относительности — трейдинговые боты располагают в соседнем с биржей здании.

Если вы будете работать в разных часовых поясах, то утилиты скорее всего будут настроены по времени центрального офиса.

Unit тестирование

Все просто. Если не писать тесты — придется при каждом изменении руками и глазами проверять одно и то же.

Если пишете фичу и руки чешутся быстренько ее руками проверить и отправить в бой, садимся на руки и автоматизируем проверку.

По факту — есть проекты без тестов, это больно и сложно.

Пирамида тестирования — мы отвечаем за нижний слой.

Быстрые и изолированные модульные тесты обычно лежат рядом с кодом и запускаются при каждой сборке приложения (сервиса).

Сервисные тестируют приложение целиком, UI тестирует GUI.

Обычно делаются снаружи — есть куча инструментов, но и то и то можно писать на Java, например Cucumber.
