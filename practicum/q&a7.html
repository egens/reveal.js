Unmodifiable vs immutable
Classes should be immutable unless there's a very good reason to make them mutable.... If a class cannot be made immutable, limit its mutability as much as possible. (Effective Java)
В Java Collections есть два понятия — unmodifiable и immutable — немодифицируемый и неизменяемый.

Unmodifiable означает невозможность изменить состав коллекции — добавить или удалить элементы.

Но коллекция мутабельных объектов остается мутабельной — можно получить и изменить объект внутри коллекции. Чтобы коллекция была иммутабельной, она должна быть немодифицируемой и соддержать в себе неизменяемые элементы.

Изменяемость — один из источников ошибок, неизменяемые объекты — потокобезопасны и делают невозможным побочные эффекты в методах (когда метод влияет на внешние объекты, в частности на аргументы).

Исключения

Важная тема, на собесах редко

Проверяемые — разработчик предусмотрел возможные проблемы при выполнении кода и показывает, что их нужно обработать. Их используют в core библиотеках, которые пишутся для внешнего пользователя.

Error — случилось что-то плохое, что лучше не продолжать работу и не пытаться исправить. Когда я писал ETL Джобы на Java, мы кидали именно ошибки, чтобы Джоб быстрее ушел в ретрай или подсветился на дашборде.

Непроверяемые — используются в остальных случаях, например при написании приложений на Spring. Там есть механизм, который позволяет инкапсулировать логику обработки непроверяемых исключений.

То есть в случае ошибок API программа кидает различные непроверяемые исключения, а обработчик знает, как подготовить ответ сервера для каждого из них.
